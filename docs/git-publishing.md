# Git 공개 범위와 복제 후 준비

저장소는 소스·문서·테스트를 공유한다. 실행 중인 Mac의 개인 설정이나 설치된 모델을 그대로 배포하는 백업이 아니다. 공개 안내의 Mac `192.0.2.10`·Windows `192.0.2.20`은 문서 전용 주소이므로 실제 연결에 사용하지 않는다.

## 포함·제외 기준

| Git에 포함 | Git에서 제외하고 별도 보관 |
| --- | --- |
| 프로젝트 `app/`, `scripts/`, 테스트와 실행 도구 | `.venv*`, 설치 환경·캐시·빌드 출력 |
| 데모·업데이트의 공개 가능한 소스와 문서 | ZIP·기타 배포 압축 파일 |
| 검증된 업데이트 `update-manifest.json` | 기본 데모의 로컬 `demo-config.json`, `demo-manifest.json` |
| 라이선스·모델 출처/고지 문서, 재현용 비밀정보 없는 manifest | 모델 가중치·ONNX·GGUF·기타 대용량 모델 파일 |
| `server.example.toml`, `.env.example`, 의존성 목록·잠금 파일 | 실제 `server.toml`, `.env`와 인증 토큰 |
| 고정 합성 입력을 사용하는 테스트 | 인증서·개인 키·`connection/`, 녹음·전사·세션 로그·내보내기·로컬 DB |

검증된 `MyVote-Speaker-Update/` 소스와 manifest 대상 파일은 원본 그대로 유지한다. 최상위 공개 안내문에서만 개인 사용자 경로와 실제 LAN 주소를 예시로 바꾼다. 라이선스·출처 고지를 포함해도 모델 파일의 배포 권한이나 인증정보까지 공개해도 된다는 뜻은 아니다.

`.gitignore`는 실수로 추가되는 로컬 파일을 줄이는 보호 장치다. 이미 추적 중인 파일의 내용을 지우거나 과거 커밋의 비밀정보를 제거하지는 않는다. 업로드할 변경 목록에서 키·토큰·실제 사용자 경로·원문 기록이 없는지 다시 확인하며, 비밀정보를 공유하기 위해 강제 추가 옵션을 사용하지 않는다. Git 작성자 이름·이메일은 파일 내용과 별도의 커밋 메타데이터이므로 공개 범위를 확인한다.

## 복제 후 음성 서버 준비

1. 프로젝트 루트에서 예시 설정을 **기존 파일을 덮어쓰지 않고** 복사한다.

   ```bash
   cp -n server.example.toml server.toml
   ```

2. Git에서 제외되는 `server.toml`의 `network.expected_ip`를 실제 Mac LAN 주소로 바꾸고, 모델 ID·경로·선택 기능을 환경에 맞춘다. 예시 주소로는 서버를 시작하지 않는다. Windows 접속 대상과 서버 인증서 SAN도 같은 실제 주소를 가리켜야 한다.
3. 별도 신뢰 경로로 기본 데모의 개인 구성, 해당 Mac용 서버 인증서·키·신뢰 CA를 준비한다. 기본 데모의 `demo-config.json`·`demo-manifest.json`은 저장소에 없으며, 공개 `update-manifest.json`으로 대체하거나 검증을 끄지 않는다. Windows 클라이언트 키와 CA 발급용 개인 키를 Mac 서버 묶음에 추가하지 않는다.
4. 필요한 ASR·VAD·화자·선택한 겹침 분리 모델을 각 라이선스에 따라 별도로 확보한다. LM Studio의 번역 모델과 오케스트레이터도 별도 다운로드·로드가 필요하다. 소스 저장소를 복제하는 것만으로 모델이 설치되지 않는다.
5. 해당 Mac에서 지원 Python으로 환경을 준비한다. 준비 도구는 `bash scripts/bootstrap.command`, 최초 데모 의존성·모델 준비는 [first-demo 안내](../first-demo.md)를 따른다. 이미 준비된 데모의 `.venv`·모델·인증서를 재사용할 수 있지만 다른 경로의 가상환경을 복사한 것만으로 동작을 보장하지 않는다.
6. `bash check-server.command`로 로컬 준비 상태를 확인한 뒤 `bash start-server.command`로 실행한다. 점검을 통과해도 실제 Windows 연결·영상·화자 품질 검증은 별도로 필요하다.

저장소의 테스트 중 검증된 엔진 검사는 데모 환경의 의존성이 필요하다. 모델·인증서가 제외되어 있으므로 새 복제에서 곧바로 전체 운영 서버가 실행된다고 기대하지 않는다. 개인 키는 저장소 밖 신뢰 경로로 전달하고 제한된 파일 권한으로 보관한다.

## 별도 텍스트 API

FastAPI 텍스트 서비스는 음성 서버와 별도다. `.env.example`을 로컬 `.env`로 복사한 뒤 관리 API 키를 새로 생성하고, `requirements.txt`와 `requirements-lock.txt`에 맞춰 전용 환경을 준비한다. 실제 `.env`는 커밋하지 않는다. 실행·인증·TLS 공개 조건은 [스트리밍 API 안내](streaming-api.md)를 따른다. 이 서비스는 음성 모델·인증서를 Git에 추가해야 동작하는 구조가 아니며 기존 Windows 오디오 앱의 자동 대체 경로도 아니다.
