# 겹친 발화의 두 줄 자막 실험판

작성일: 2026-09-15. 엔진 식별자: `live-overlap-2026-09-15`.

이 문서는 첫 통합판의 동작·검증 기록이다. 후속 엔진 식별자와 최신 Mac ZIP·옵션은 [주파수·화자 실험판 안내](frequency-speaker-preview.md)를 따른다.

**주파수 분리 → 두 음성 각각 전사·번역 → Windows 두 줄 자막까지 실시간 코드 경로를 연결했다.** 기본 실행에서는 꺼져 있고, 아래 옵션으로 선택한다. 실제 Mac과 사용자 영상에서 이 새 통합 경로의 정확도·처리 지연을 아직 검증하지 않았다. 분리 출력 A/B는 사람의 이름이나 확정 화자 ID가 아니며, 기존의 모든 화자 미확정 문제를 해결했다고 주장하지 않는다.

## 작동 방식

원음의 첫 자막은 계속 생성한다. 화자 모델이 실제로 두 사람의 동시 발화를 예측한 부분은 최근 원음을 보관한 별도 작업자가 ConvTasNet과 시간·주파수 마스크로 분리한다. 두 출력에 각각 전사와 번역을 수행한다. 두 문장과 번역이 모두 준비되면 원래 혼합 자막을 한 번에 교체한다. 겹침 밖에 있던 원래 문장의 단어는 시간과 텍스트를 보존하여 별도 문맥 자막으로 남긴다.

이미 사용자가 화자를 지정한 자막은 자동 교체하지 않는다. Windows 기록에서 분리 결과를 미리 보고 **분리 결과 적용**을 선택할 수 있다. 부모에 지정한 이름을 두 사람에게 임의로 복사하지 않는다. 늦게 도착한 과거의 보완 결과는 기록과 내보내기를 갱신하지만 지금 표시 중인 최신 자막을 과거로 되돌리지 않는다.

원음 전사 대기 작업이 분리 전사보다 우선하며, 번역도 같은 서버에 한 요청씩 진입시켜 일반 자막을 우선한다. 실행 중인 모델 호출은 선점할 수 없으므로 지연 증가가 없다는 보장은 아니다. 보완 작업의 기본 기한은 **원음 끝 프레임을 서버가 받은 시점부터 15초**이며, 일반 번역의 2.5초 기한과 별도로 기록한다. 분리 실패·기한 초과·양쪽 전사 중 하나의 실패·안전하게 보존할 수 없는 단어 경계에서는 원래 자막이 유지된다.

## Mac에 복사할 파일

1. `artifacts/live-overlap-ready-2026-09-15/MyVote-Speaker-Update.zip`
2. `artifacts/models/convtasnet-libri2mix-16k-e1ef95ab7a03/pytorch_model.bin`

개발 PC의 공통 경로는 `C:\Users\seong\PycharmProjects\MyVote\`이다. ZIP에는 모델·인증서·개인 키가 없다. 모델 파일은 **20,394,640바이트**, SHA256은 `8d97f012f7b2f22bb79cb0d0983a7ba27a52c1796ee3f63cbf25b4d28630adce`이며 엔진이 일치 여부를 확인한다. 새 모델을 LM Studio에 올릴 필요는 없다.

기존 Mac 데모 서버를 Ctrl+C로 종료하고, ZIP을 새 폴더에 푼다. 폴더 이름을 `MyVote-Speaker-Update`로 두고 모델을 Downloads에 복사했다면 다음 명령으로 실행한다.

```bash
bash "$HOME/Downloads/MyVote-Speaker-Update/start-update.command" \
  "$HOME/Downloads/MyVote-Mac-Demo" \
  --experimental-overlap-model "$HOME/Downloads/pytorch_model.bin" \
  --overlap-threads 1
```

실제 폴더 위치가 다르면 경로를 바꾼다. 기존 데모의 가상환경·Whisper·화자 모델·인증서와 LM Studio 번역 서버를 재사용한다. 설치나 다운로드 옵션은 필요 없다. Torch CPU 스레드는 시작 시 고정한다. 모델과 주파수 처리의 이전 비교 및 제한은 [분리 알고리즘 문서](frequency-separation.md)에 있다.

겹침 기능을 끄려면 서버를 종료한 뒤 같은 명령에서 `--experimental-overlap-model`과 그 경로를 빼고 실행한다. 기존 데모 설치 파일은 덮어쓰지 않는다.

## Windows 실행과 확인

새 Windows 빌드 경로는 `artifacts/windows-live-overlap-2026-09-15/app/MyVote.Desktop.exe`이다. `artifacts/windows-live-overlap-handoff-2026-09-15/`의 바로가기는 기존 연결 설정을 복사해 이 빌드를 실행하도록 준비한다. 이전 Windows Preview는 새 자막 묶음 기능을 협상하지 않으므로 이전 빌드만 실행하면 일반 혼합 자막만 받는다.

1. 새 빌드를 열고 **시작**을 누른다.
2. **자막 창 열기**로 오버레이를 연다. 필요하면 **백그라운드로 숨기기**와 **마우스 클릭 통과**를 사용한다.
3. 사용자 영상의 40분대처럼 발화가 겹치는 구간을 재생한다.
4. 보완이 성공하면 같은 구간의 두 문장이 기록에 남고, 현재 표시 구간이면 오버레이에 두 행이 나타난다. 늦게 완성된 과거 결과는 기록에서 확인한다.
5. 화자를 직접 지정한 부모 자막을 기록에서 선택하면 보류된 분리 결과 미리보기가 나타난다. **분리 결과 적용**으로 선택을 반영한다. SRT/VTT는 현재 사용자가 선택한 자막을 내보낸다.

새 서버의 `session.started`에는 `engine_revision`, `capabilities: ["caption_groups_v1"]`, `overlap_status: configured_experimental`이 나타난다. 구형 클라이언트와 연결하면 분리 모델을 호출하지 않고 `client_not_supported`를 기록한다.

## 구현과 검증의 범위

- PCM 기록은 최대 20초, 실행 중 작업 하나와 최신 대기 작업 하나로 제한한다. 간격·캡처 epoch가 바뀌면 이어 붙이지 않는다.
- 공유된 실제 음성의 상관관계로 창 사이 A/B 순서를 맞춘다. 근거가 부족하면 새 익명 lane으로 시작하며 사람 ID를 만들지 않는다.
- 분리된 두 채널의 같은 단어도 각각 보존한다. 전사 상태·번역 문맥을 원음이나 상대 채널과 섞지 않는다.
- 단어 시각·부모 revision·원 트랙·epoch·용량을 검증한 후 자막 묶음을 원자적으로 반영한다. 잘못된 묶음은 부모와 이벤트 순서를 부분 변경하지 않는다.
- 실제 루프백 mTLS, Python 자막 저장소와 Windows 파서, 소유한 테스트 프로세스에서 Dispatcher·XAML 두 행 및 적용 명령을 검사한다. 이 검사는 명시적인 음성/번역 fixture를 사용한다.

실제 한국어 겹침 음성에서 두 화자의 누락·중복·잘못된 문장이 얼마나 줄어드는지, M4 Max에서 원음 자막 지연이 유지되는지, 보이는 오버레이와 장시간 실행이 정상인지는 별도 검증 대상이다. 이전 파일 분리 실험 점수만으로 이 경로를 기본 활성화하지 않는다.

최종 Python 회귀 검사 **660개 통과, 생략 0개**. Windows 계약 검사는 **125개 통과**했다. 기존 Mac 서버에는 미리 분리한 8초 WAV를 원음·A·B 순서로 각각 전송해 750개 프레임 모두 전달, 전사 자막과 번역 18개 완료, 세 세션 정상 종료를 확인했다. 새 live 분리기는 이 Mac에 아직 설치하지 않았으며, 한국어→한국어 처리라 언어 간 번역 품질 검증도 아니다. 세 세션 모두 확인된 새 화자 ID는 없었다.
