# 동일 언어 보정과 문맥 재검토 업데이트

엔진 식별자: `context-refinement-2026-09-15`.

## 동작

- 원문 언어와 출력 언어가 같으면 번역 대신 전사 보정을 요청한다. 최근 최대 4개 원문 발화를 참고해 인식 오류와 문장부호를 보정하고, 원래 전사 텍스트는 보존한다. 자동 언어 선택일 때는 ASR이 알려준 언어로 판단한다.
- 서로 다른 언어이면 기존 번역 경로를 사용한다.
- 첫 보정·번역은 기존 지연 예산으로 먼저 전송한다. 후속 발화가 도착하면 낮은 우선순위 작업이 앞선 완료 자막을 재검토한다. 바꿀 내용이 있을 때만 같은 자막 ID의 결과를 새 수정 번호로 교체한다.
- 원문, 원음 시각, 화자 정보는 재번역 때문에 바뀌지 않는다. 수동 화자 지정이 있는 자막, 이전 소스 수정판, 다른 모델 실행 세대, 숨겨지거나 교체된 자막에는 오래된 재검토 결과를 적용하지 않는다.
- 화면의 같은 언어 자막은 `원문 · 보정`으로 표시한다. 번역과 보정 결과 모두 SRT/VTT/JSON 내보내기에 반영된다.

프롬프트는 숫자·부정·이름·불확실성을 유지하고, 원문에 없는 사실·요약·말투 변경을 추가하지 않도록 요청한다. 이는 실제 의미 보존을 보장하는 검증기가 아니다. 실제 모델과 영상에서 과잉 보정 여부를 확인해야 한다.

## 속도와 문맥 범위

첫 결과는 문맥 재검토가 끝날 때까지 기다리지 않는다. 재검토는 한 번에 최대 2개 자막, 작업 1개와 최신 대기 1개, 요청 사이 최소 2초다. 첫 토큰은 대기 포함 2초, 전체 응답은 대기 포함 4초 한도로 처리하며 완성된 JSON만 검증한다. 잘못된 응답이나 시간 초과는 기존 자막을 유지한다. 원자적으로 묶은 수정 중 하나라도 오래된 상태이면 전체 묶음을 거절한다.

현재 재검토 문맥은 **지금까지 받은 원문 중 최근 최대 64개 발화·16,000자**다. 앞선 자막은 최신 발화 기준 최대 120초 범위에서 검토하며 한 자막의 성공 수정은 최대 2회다. 아직 도착하지 않은 말이나 긴 영상 전체를 한 번에 이해하는 기능은 아니다. 오래된 내용의 요약을 사실처럼 합성해서 문맥에 넣지 않는다. 이 한도는 메모리 제한이며, 모델마다 다른 토큰 창에 들어간다는 보장은 아니다.

대기 중인 첫 번역 작업이 먼저 실행된다. 이미 LLM이 처리 중인 재검토를 물리적으로 즉시 중단한다는 보장은 없어, 실제 Mac의 지연 영향은 따로 측정해야 한다. 4초 설정은 지연 목표나 실측 결과가 아니다.

## 옮길 파일과 실행

Mac에는 다음 최신 ZIP을 복사한다.

`artifacts/context-refinement-ready-2026-09-15/MyVote-Speaker-Update.zip`

ZIP을 다운로드 폴더에 새로 풀고 이전 서버를 Ctrl+C로 종료한 뒤:

```bash
bash "$HOME/Downloads/MyVote-Speaker-Update/start-update.command" \
  "$HOME/Downloads/MyVote-Mac-Demo" \
  --experimental-overlap-model "$HOME/Downloads/pytorch_model.bin" \
  --overlap-threads 1
```

기존 데모 가상환경·전사 및 화자 모델·인증서·분리 모델을 재사용한다. 새로운 분리 모델 다운로드는 필요 없다. 기존 업데이트 폴더와 섞지 않도록 이전 폴더 이름을 바꾼 뒤 압축을 푼다. 주파수 분리 옵션 없이 실행해도 원문 보정과 문맥 재검토를 사용할 수 있다.

Windows에서는 함께 준비하는 새 **MyVote Context Preview**를 사용한다. 이전 프로그램을 트레이의 `종료`로 끝낸 후 새 바로가기를 연다. 새 클라이언트가 `caption_refinement_v1`을 협상한 세션에서만 서버의 문맥 재검토가 켜진다. 이전 클라이언트에는 기존 단일 결과 경로를 제공한다. 화자 활동 연구 옵션은 기본 꺼짐이다.

## 확인 순서

1. 원문 언어 `자동`, 출력 언어 `한국어`, `시작 → 자막 창 열기`를 선택한다.
2. 한국어 영상에서는 원문과 보정 결과를 확인한다. 영어 영상에서는 원문과 한국어 번역을 확인한다.
3. 뒤 문장에서 이름·대상·의미가 명확해지는 구간을 재생하고, 앞선 자막의 결과만 바뀌는지 확인한다. 문맥을 검토했다고 반드시 수정하는 것은 아니다.
4. `중지` 후 세션의 `events.jsonl`에서 `caption.results_revised`, `session.json`에서 `translation.result_revision` 증가를 확인한다. 원문·시각·source_revision은 유지되어야 한다.

## LM Studio 모델을 교체할 때

LM Studio에서 새 채팅 모델을 로드한 뒤 서버를 새 모델 ID로 다시 시작한다. 같은 `/v1/chat/completions` 스트리밍 인터페이스라면 어댑터 코드를 다시 만들 필요는 없다. 서버는 시작 시 선택한 ID를 요청에 사용하므로 UI의 로드 모델만 바꾸고 기존 서버를 계속 실행하는 방식은 확실한 교체 절차가 아니다.

모델 목록은 Mac에서 확인한다.

```bash
curl http://127.0.0.1:1234/v1/models
```

새 모델을 지정하는 예:

```bash
bash "$HOME/Downloads/MyVote-Speaker-Update/start-update.command" \
  "$HOME/Downloads/MyVote-Mac-Demo" \
  --llm-model "목록의-정확한-모델-ID" \
  --experimental-overlap-model "$HOME/Downloads/pytorch_model.bin" \
  --overlap-threads 1
```

공통 프롬프트와 스트리밍 파서를 재사용한다. 모델이 지시를 따르는지, JSON 재검토 응답을 완성하는지, 문맥 창과 지연 예산이 맞는지는 재시험한다. 현재 LM Studio 어댑터는 reasoning 출력을 거절하므로 지원하는 모델에서는 Thinking을 끈다. 전사 모델·화자 모델·음원 분리 모델을 교체하는 경우에는 별도 어댑터와 프로필 검증이 필요하다.

공식 근거: [LM Studio 채팅 API](https://lmstudio.ai/docs/developer/openai-compat/chat-completions), [모델 목록 API](https://lmstudio.ai/docs/developer/openai-compat/models). 목록은 JIT 로딩 설정에 따라 다운로드된 모델도 포함할 수 있다.
