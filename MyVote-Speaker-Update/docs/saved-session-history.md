# 저장된 자막 다시 열기

`history-latency-2026-09-16`에 포함한다. 새 Windows 앱의 **저장된 자막**에서 지난 세션을 선택해 **기록 열기**를 누른다. Mac 서버가 꺼져 있어도 원문·번역/보정·화자 이름을 확인하고 화자를 다시 지정하거나 SRT/VTT/JSON으로 내보낼 수 있다. 과거 기록은 오버레이에 표시하지 않는다.

## 보존하는 내용

- 기존 `session.json`의 원음 시각, 원문 번호, 별도 번역 재수정 번호 `result_revision`, 같은 언어 보정 역할.
- 수동 화자 이름/지정과 자동 변경을 막는 수동 지정 상태.
- 이미 적용된 두 겹침 자막과 숨긴 혼합 원문, 아직 적용하지 않은 보류 분리 결과.
- 예전 모델의 완료 결과 및 오래되어 적용할 수 없는 보류 결과. 다시 열었다고 이를 최신 추론으로 표시하지 않는다.

앱을 새로 시작한 뒤에도 편집한 세션 파일을 다시 읽는다. 기록을 다시 여는 것은 녹음이나 추론 세션 재개가 아니다. 새 실시간 입력은 **자막 시작**으로 별도 세션을 만든다.

## 사용 순서

1. 실시간 자막이 진행 중이면 **중지**하고 저장 완료를 기다린다.
2. **저장된 자막** 목록에서 날짜·구간 수를 보고 선택한다. 새로 저장한 기록은 **새로고침**으로 찾는다.
3. **기록 열기** 후 원하는 자막과 화자를 선택해 **이름 변경**, **선택 구간에 지정**을 사용한다.
4. **이중 언어 자막 저장**으로 해당 세션 아래 새 `exports/<ID>` 폴더에 SRT/VTT/JSON 결과를 저장한다.

기록 목록은 앱에 설정된 기록 폴더의 `32자리 세션 ID/session.json`을 읽는다. 최근 최대 100개를 표시하고, 기록 한 개에서 최대 10,000개 자막 ID를 복원한다. 깨지거나 지원하지 않는 파일은 목록에서 제외한 수를 표시한다. 녹음 도중 앱/OS가 비정상 종료되어 아직 `session.json`이 만들어지지 않은 기록의 journal 복구는 이번 범위에 포함하지 않는다.

## 불러오기와 저장 방식

파일 전체를 검증한 뒤 서버 접속 없이 로컬 백엔드에서 연다. 창에는 최대 100개 항목씩, 512KiB 이하의 페이지로 전송한다. 창은 페이지 ID·순서·개수·화자 목록이 모두 맞을 때 새 기록으로 화면을 바꾼다. 불러오기가 실패하면 화면에 남아 있는 이전 기록을 다른 파일에 잘못 수정하지 않도록 편집을 잠근다. 다시 열거나 새 실시간 세션을 시작하면 정상 선택 상태로 돌아간다.

원래 파일의 세션 ID를 유지하고, 창/백엔드 통신에는 매번 새로운 보기 ID를 사용한다. 오래된 실시간 결과를 다시 연 기록에 붙이지 않는다. 편집 시 JSON/SRT/VTT를 기존 저장 경로에 갱신하며 내보내기는 새 하위 폴더를 만든다. 기록은 로컬 파일 기반이다. 동시 다중 앱 편집, DB 검색, 무제한 장시간 기록, 자동 journal 재구성은 별도 기능이다.

## 검증

Python 회귀 820개, 실제 Python 백엔드와 WPF 화면 로직의 계약 검사 215개가 통과했다. 시험용 자막을 사용해 2,104개 표시 자막의 페이지 전달, r2 보정·수동 화자·같은 언어 보정·보류/적용 분리, 편집 후 새 백엔드/창 모델의 복원을 확인했다. 실제 사용자 창의 다중 모니터·DPI 사용성 및 새 Mac 모델 성능 검사와는 구분한다.

원시 검증 기록은 개발 PC의 프로젝트 경로 `artifacts/session-history-validation-2026-09-16/README.md`에 있다. 이 검증 폴더는 Mac 업데이트 ZIP에 포함하지 않는다.
