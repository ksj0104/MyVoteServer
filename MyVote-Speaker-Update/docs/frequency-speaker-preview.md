# 주파수 분리·짧은 발화 화자 분석 실험판

작성일: 2026-09-15. 엔진 식별자: `frequency-speaker-preview-2026-09-15`.

겹친 발화에는 **ConvTasNet → STFT 전력 비율 마스크 → 두 음성 각각 전사·번역**을 적용한다. 기존 일반 자막을 먼저 표시하고, 두 결과가 준비되면 보완한다. [분리 알고리즘과 실제 비교](frequency-separation.md), [두 줄 자막 동작](live-overlap.md).

단독 발화가 짧아 화자 판단에 사용되지 않는 문제에는 별도의 선택 기능 `--experimental-speaker-pooling`을 추가했다. 분리 모델이 만든 A/B를 사람 이름으로 등록하는 기능과는 다르다. 이 기능도 실제 화자 정확도 개선이 입증된 기본값은 아니다.

## 짧은 발화를 사용하는 방법

- 현재 최대 10초 분석 창에서 모델이 단독 발화로 예측한 200ms 이상·1초 미만 구간만 보류한다. 기존 신뢰도 0.8 기준을 유지한다.
- 보류한 시각을 다음 분석 창에서 다시 검사한다. 현재 창 안에서 같은 로컬 화자로 예측된 실제 음성 1~3초를 모아 임베딩을 한 번 계산한다. 창의 화자 번호를 다음 창의 사람 ID로 간주하지 않는다.
- 모인 음성 전체가 확인 근거 한 번이다. 동일 음성을 재사용해 확인 횟수를 늘리지 않는다. 실제 발화 시각을 별도로 보존하여 중간의 침묵이나 다른 사람의 말에는 이 화자를 지정하지 않는다.
- 겹침·낮은 신뢰도·무음·클리핑 기준 초과 구간은 사용하지 않는다. 보류 구간은 최대 32개이며, 분석 창에서 빠지거나 입력이 끊기거나 종료되면 명시적으로 정리한다.

원 파형 조각을 이어 붙이면 접합부의 음향 특징과 평균 정규화가 바뀔 수 있다. 같은 로컬 화자라는 모델 예측도 틀릴 수 있다. 따라서 임계값을 낮춰 화자 수만 늘리는 대신, 정답 주석이 있는 음성의 오지정·미지정 시간과 실제 자막의 화자 부착 여부를 비교한다. 이 구현은 새로운 학습 모델이나 논문 전체의 재현이 아니다.

구간을 모으는 연구 근거와 pyannote의 실제 구현과의 차이는 [논문·코드 조사](speaker-pooling-research-2026-09-15.md)에 정리했다.

## 실제 음성 비교 결과

동일한 모델·설정으로 각 120초 입력을 비교했다. AMI 두 구간은 이전에 이미 관찰한 회귀 입력이며, 단어 기반 화자 주석으로 계산한 아래 시간은 표준 DER 점수가 아니다. 신규 ID가 만들어졌을 때의 발화 근거로 정답 화자를 사후 대응한 후, 단독 발화에서 잘못 지정된 시간과 미확정 시간을 계산했다.

| 입력 | 잘못 지정된 시간: 기존 → 풀링 | 미확정 시간: 기존 → 풀링 |
|---|---:|---:|
| AMI IS1009a | 0 → 0.290초 | 35.802 → 36.088초 |
| AMI ES2004a | 0 → 0초 | 32.523 → 30.747초 |

사용자 영상 40:00–42:00에서는 예측 ID가 2개에서 3개로 늘고, 최초 확정 분석 시점은 클립 시작 후 51.392초에서 41.312초로 앞당겨졌다. 하지만 **실제 Mac에서 저장했던 원문 자막 90개를 현재 mapper로 재생했을 때 화자가 붙는 자막은 4개에서 5개로만 늘었다.** 영상의 화자 정답이 없어 올바른 사람을 구분했는지는 이 수치로 판단할 수 없다. 이전 실제 Mac 실행의 90개 전부 미확정 결과와 이번 오프라인 재생은 다른 실행이다.

한 회의 입력에서 오지정과 미확정이 증가했으므로 풀링을 기본값으로 승격하지 않는다. 모든 화자 미확정 문제의 해결판으로 보지 않는다. 최종 비교는 실제 분할 모델 180회·임베딩 227회, 입력·소스 해시 유지와 정확한 120초 구간 회계 검사를 통과했다. 모델 호출 계측 코드 수정 전의 별도 시도 60회·41회는 최종 비교 수치에 합치지 않았다. 처리 속도·화면 지연은 이 순차 오프라인 실행에서 평가하지 않았다.

개발 PC의 상세 기록: `artifacts/speaker-pooling-2026-09-15/comparison-v2/summary.json`. 원래 주파수 마스크의 통제 혼합 비교도 모델 출력만 사용한 경우보다 점수가 낮았으므로 두 실험 모두 선택 옵션으로 유지한다.

## Mac 실행

개발 PC의 다음 두 파일을 Mac Downloads에 복사한다.

1. `artifacts/frequency-speaker-ready-2026-09-15/MyVote-Speaker-Update.zip`
2. `artifacts/models/convtasnet-libri2mix-16k-e1ef95ab7a03/pytorch_model.bin` — 약 20.4MB.

ZIP에는 모델·인증서·개인 키가 없다. 압축을 새 `MyVote-Speaker-Update` 폴더에 풀고, 기존 서버를 Ctrl+C로 종료한 뒤 실행한다.

```bash
bash "$HOME/Downloads/MyVote-Speaker-Update/start-update.command" \
  "$HOME/Downloads/MyVote-Mac-Demo" \
  --experimental-overlap-model "$HOME/Downloads/pytorch_model.bin" \
  --overlap-threads 1
```

이 명령은 주파수 분리·두 줄 자막 실험을 켠다. 짧은 발화 화자 분석도 시험하려면 맨 뒤에 `--experimental-speaker-pooling`을 추가한다. 비교할 때는 옵션 하나만 바꿔 같은 영상을 재생한다. 두 기능은 각각 지정한 경우에만 켜진다.

기존 Mac 가상환경, Whisper, 화자 모델, 인증서와 LM Studio 번역 모델을 재사용한다. 새로운 LM Studio 모델 다운로드나 로드는 필요 없다. 위 경로가 실제 폴더와 다르면 수정한다.

## Windows 확인

바탕화면의 **MyVote Overlap Preview**를 사용한다. 이전 앱이 켜져 있으면 트레이에서 **종료**한 뒤 연다. **시작 → 자막 창 열기**를 선택하고 사용자 영상의 40분대를 재생한다. 이 서버 업데이트는 준비된 Overlap Preview의 자막 프로토콜과 호환된다.

연결 기록의 `engine_revision`이 위 식별자인지 확인한다. 짧은 발화 옵션을 켰으면 서버 화자 설정의 `short_speech_pooling.enabled`가 `true`다. 주파수 분리는 `overlap_status: configured_experimental`로 기록된다. 분리된 A/B는 익명 출력이며, 새로운 사람 두 명이 확인됐다는 뜻이 아니다.

이번 소스가 실제 Mac에 설치·실행된 것과 M4 Max 지연은 아직 확인하지 않았다. 기존 Mac 서버에 미리 분리한 WAV를 보내 전사·번역을 확인한 기록은 새 서버 통합 검증을 대신하지 않는다.

최종 Python 회귀 검사 **696개 통과, 생략·실패·오류 0개**. 실행 중 소스 해시가 유지됐으며, 짧은 발화·정확한 시각·겹침 차단·gateway 옵션 선택·Mac 소스 ZIP과 기존 자막 경로를 검사했다. 실제 Silero·분할 모델·SepFormer의 선택 검사도 포함한다. Windows 실행 파일은 이번에 다시 빌드하지 않았고, 기존 Overlap Preview의 서버 자막 프로토콜을 사용한다. 기록은 `artifacts/validation-frequency-speaker-2026-09-15/summary.json`에 있다.
